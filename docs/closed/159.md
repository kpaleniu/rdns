### 159. `--host ::` is dual-stack on Linux and IPv6-only on Windows — **filed 2026-10-02, closed 2026-10-03**, **enhancement**, **ready-for-agent**, after #153 and #158

Found grilling #158. Nothing in the tree sets `IPV6_V6ONLY`, so an IPv6
wildcard bind takes the OS default: 0 on Linux (dual-stack; checked under
WSL2, kernel 6.18), on on Windows (Microsoft's dual-stack sockets
documentation). The same `--host ::` therefore serves IPv4 clients on one
platform and not the other, with nothing at startup saying which. Making it
agree means setting the option explicitly at every IPv6 wildcard bind —
both daemons' UDP sockets, the TCP listeners, and the sockets quinn and
hyper bind — through `socket2`, already in the lock under quinn (#69).

> *This was generated by AI during triage.*

**Triaged 2026-10-02**, measured on both sides with one probe:

| | `IPV6_V6ONLY` default | IPv4 client to a `[::]` listener |
|---|---|---|
| Linux (WSL2, kernel 6.18) | 0 | accepted, peer `::ffff:127.0.0.1` |
| Windows | 1 | connection refused |

Twelve production listener binds, six per daemon: UDP, TCP, metrics, DoT,
DoH, and DoQ's `quinn::Endpoint::server`, which binds its own socket. #153
merges the three encrypted ones. `--host` takes one address, and its help
says only "Address to listen on, for both transports". No tracked
configuration binds `::` — the image, the four interop configs and every
documented example use `0.0.0.0` or `127.0.0.1` — so the shipped image
serves no IPv6, and today the only way to serve both families is `::` on
Linux, by the kernel's default.

What the others do (§4): Knot's `listen` is "One or more IP addresses",
with "`::` for all configured IPv6 addresses"; NSD's `ip-address` "Can be
given multiple times", with `do-ip4` and `do-ip6`. Neither documents its
`IPV6_V6ONLY`.

Grilled to a design (Q1-Q4); recorded as `docs/adr/0006`. Decided, and
rejected on the way:
- **`::` is dual-stack on both platforms**: `IPV6_V6ONLY` 0 on every IPv6
  listener bind. Rejected: IPv6-only everywhere with a repeatable `--host`
  (the peers' model), which costs a repeatable listen address at every site
  and would make #158's canonicalization the wrong fix, since without a
  dual-stack socket a mapped peer is only ever a spoofed UDPv6 datagram the
  family rule already refuses; a flag for either, which is two meanings of
  `::` to test on two platforms.
- **No flag.** A specific IPv6 address cannot receive IPv4, so it is the
  off switch, and `--host`'s help says so.
- **One bind helper** in `rdns-transport` for every listener, not a
  setsockopt at twelve sites (§7).
- **The families served are said out loud**, at startup and by
  `--check-config`, read from the socket as bound (§14).
- Outbound sockets are unaffected: `bind_addr_for` binds `[::]:0` only to
  reach an IPv6 target.

No glossary term; dual-stack is a general one.

#### Agent brief

**Category:** enhancement
**Summary:** Make `--host ::` serve IPv4 and IPv6 on every platform, and say
which families each listener serves.

**Current behavior:** IPv6 listener binds take the OS default for
`IPV6_V6ONLY`, so `::` is dual-stack on Linux and IPv6-only on Windows, and
nothing reports which.

**Desired behavior:**
- A bind helper in `rdns-transport`, using `socket2`, for UDP sockets and
  TCP listeners. On an IPv6 address it sets `IPV6_V6ONLY` to 0 before
  binding; on any address it reports the families the bound socket serves.
- Every listener in both daemons binds through it: the UDP socket, the TCP
  listener, the metrics listener, DoT, DoH, and DoQ, whose quinn endpoint is
  built over a socket from the helper rather than binding its own.
- The startup line and `--check-config` name the families per listener, for
  example `[::]:53 (IPv4 and IPv6)` or `0.0.0.0:53 (IPv4)`.
- `--host`'s help says `::` serves both families and a specific IPv6 address
  serves IPv6 only.

**Key interfaces:**
- The helper's bind functions return the bound socket and its families;
  bind failures keep naming the flag, as today.
- #153's bound encrypted-listener value uses the helper.

**Acceptance criteria:**
- [ ] A test binds `[::]` through the helper, then an IPv4 client is
      answered over UDP and over TCP and the family report reads IPv4 and
      IPv6. It runs on Windows and Linux; it is shown failing on Windows
      against the current code, and the commit says it passes on Linux
      either way.
- [ ] No `UdpSocket::bind`, `TcpListener::bind` or `quinn::Endpoint::server`
      for a listener remains outside the helper.
- [ ] The commit names Windows' behavior change: `::` now serves IPv4.
- [ ] Workspace tests and clippy on Windows and Linux; fmt, doc and the §12
      grep clean.

**Out of scope:**
- A repeatable `--host` (`docs/adr/0006`).
- Outbound sockets.

**Closed 2026-10-03**, `a842f47`. As decided in `docs/adr/0006`, with one
point the ADR could not keep:

- **`--check-config` cannot read families "from the socket as bound"**: it
  exits before anything binds (§15). It names what `bind::planned` says the
  bind will make of the address — the rule the helper applies — and the
  startup line reads them from the sockets. A hostname has no planned
  families and is printed as given.

The helper keeps what std's bind did (`SO_REUSEADDR` on a Unix stream
socket, backlog 128, each resolved address in turn), so the only behaviour
it changes is the option it exists for. DoQ is built with
`quinn::Endpoint::new` over a socket from the helper. The startup lines'
"per client" for the two limiters, left behind by #157, went with it.

`the_ipv6_wildcard_serves_ipv4_clients` fails on Windows with the option
left at the OS default, and passes on Linux either way — checked by running
that mutant on Linux. `rdnsd --host ::` on Windows answered an IPv4 client.
1411 tests on Windows, 1432 on Linux.
