### 170. DoH ignores `max_inflight_per_connection`: 200 queries a connection, where TCP and DoQ allow 16 — **filed 2026-10-05, closed 2026-10-05**, **bug**

Found grilling #169. `TransportLimits::max_inflight_per_connection`, 16, is
read by `tcp.rs` (a semaphore per connection) and by `quic.rs`
(`max_concurrent_bidi_streams`); `https.rs` never reads it. hyper's HTTP/2
server advertises `max_concurrent_streams` 200 by default
(`hyper-1.11.1/src/proto/h2/server.rs:69`), so one DoH connection runs 200
queries at once — `CLAUDE.md` §7's shape, two siblings right and one written
separately.

| | per connection | per source (32 connections) | per listener (128) |
|---|---|---|---|
| TCP, DoT | 16 | 512 | 2048 |
| DoQ | 16 | 512 | 2048 |
| DoH over HTTP/2 | 200 | 6400 | 25 600 |

For `rdnsr` each is a resolution of up to 10 s (#168), with its own upstream
socket per exchange. HTTP/1.1 is one request at a time and not affected.

**Brief:** `http2::Builder::max_concurrent_streams(limits.max_inflight_per_connection)`
in `https.rs`. Checked in h2 0.4.19: a stream past the advertised limit is
refused with `RST_STREAM(REFUSED_STREAM)` (`proto/streams/recv.rs:151`,
`:1064`), which RFC 9113 §8.7 says "can be safely retried" because nothing
was processed. A test opens 17 streams on one connection to a handler that
holds them and reads one refusal; watched failing without the setting.

**Closed 2026-10-05**, `4fcfb5e`. As briefed. The test writes HTTP/2 frames and
HPACK by hand: a conforming client honours the advertised limit and queues
the seventeenth stream itself, so it could not show the refusal. h2 applies
its own SETTINGS only once acknowledged, so the test ACKs before opening
streams. Watched failing without the setting: nothing refused within 1 s.
1458 tests on Windows, 1479 on Linux.
