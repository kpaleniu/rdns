### 156. RFC 7766 §10's other connection limits — **filed 2026-10-02, closed 2026-10-03**, **enhancement**, **ready-for-agent** after #155 and #157

Split out of #155. RFC 7766 §10 lists five "configurable connection
management options"; #155 takes two (total connections, idle timeout). The
other three have no setting and no mechanism here: maximum TCP connections
per source IP address or subnet, maximum DNS transactions per TCP
connection, and maximum TCP connection duration. `RateLimit` limits queries
per source, not connections. Of the peers in #155, NSD has `tcp-query-count`
(default 0, no maximum); Unbound's `max-reuse-tcp-queries` is its outgoing
connections' and not this. ~~Per-source connection limits were not looked
up.~~ **Looked up 2026-10-02:** below. ~~One decision covers all three:
whether `rdns` follows §10 beyond what the peers ship.~~ **They split**: one
of the three addresses a single-source exposure the others do not.

> *This was generated by AI during triage.*

**Triaged 2026-10-02**, grilled to a design (Q1-Q11). **Narrowed to
per-source concurrent connections.** Transactions per connection and maximum
duration are rejected in `.out-of-scope/connection-turnover-limits.md`: a
client cut off by either reconnects, and a duration cap truncates long AXFRs.

**The exposure, from reading, not reproduced.** `RateLimit::PerConnection`
(`rdnsr`) charges one query token when a connection opens, so it limits how
fast a peer opens connections, not how many it holds; `rdnsd` uses
`PerMessage`, so opening costs nothing. One peer can open 128 connections to
a listener and keep each alive with a query every 9 s, under the 10 s idle
timeout, holding every slot. #155 makes that visible, not impossible.

**What the others ship (§4):** Unbound `tcp-connection-limit <netblock>
<limit>`, off by default — "When at the limit, further connections are
accepted but closed immediately". BIND has none: `tcp-clients` "is per
server address, not per client IP address" (ISC KB). Knot has none. NSD was
not checked for this one.

Decided, and rejected on the way:
- **On by default, 32 per source per listener**, a behavior change the
  commit names. RFC 7766 §6.2.2 asks clients for about one connection per
  purpose and says a server's per-client limits "SHOULD be much looser than
  the client guidelines"; 32 is about ten times a conforming client and a
  quarter of a listener. Off-by-default (Unbound) leaves the exposure as the
  default; a fraction of `max-connections` couples two settings.
- **0 turns it off**, unlike #155's refusal: the total limit still bounds
  descriptors, and §14 asks for an off switch.
- **A source is an IPv4 address or an IPv6 /56** — `CONTEXT.md`'s
  **Source**; the exact address is the **Peer**. /56 is BIND's
  `ipv6-prefix-length` default; its IPv4 /24 is not followed, because for a
  concurrent-connection limit it lumps unrelated customers behind shared
  hosting or carrier NAT. A per-peer key is defeated by rotating within a
  /64. The type is #157's, so the grouping is built once.
- **Accept, then close.** Not a choice: the peer's address is known only
  from `accept`, so a per-source check cannot precede it the way #155's slot
  wait does.
- **Per listener**, as #155: a shared count would deny DoT to a source busy
  on TCP while DoT has slots.
- **Its own exemption list**, parsed by `TransferAcl::parse_named` (§7).
  Reusing `query-rate-exempt` would couple two policies.
- **A counter with no per-address label**, plus a log line at most once per
  source per minute naming it. A label per address is §5's unbounded table
  in the scrape; a line per refusal lets the attacker set the log volume.

No ADR: a constant and two settings are reversible; the reason for /56 goes
on the source type.

#### Agent brief

**Category:** enhancement
**Summary:** Limit how many concurrent connections one source may hold on
each stream listener.

**Current behavior:** each of TCP, DoT, DoH and DoQ has a total connection
limit (#155) and no per-source one; one peer can occupy every slot.

**Desired behavior:**
- Shared `[server]` settings in both daemons:
  `--max-connections-per-source` / `max-connections-per-source` (default 32,
  `0` = off) and `--max-connections-per-source-exempt` /
  `max-connections-per-source-exempt` (addresses and CIDR prefixes, parsed
  as `query-rate-exempt` is; an error names the setting).
- Each listener counts open connections per **source** using #157's source
  type. After #155's slot is taken and the connection accepted, a
  non-exempt source already at the limit has the connection closed at once,
  with no DNS reply, and its slot released. Exempt sources are not counted.
- A source's entry exists only while it has an open connection, so the
  table cannot exceed the listener's `max-connections`.
- `dns_connections_refused_per_source_total{transport}` counts refusals; a
  log line names the source, at most once per source per minute.

**Key interfaces:**
- #157's source type: the only peer-to-source mapping; nothing here
  re-derives the /56.
- #155's per-listener slot machinery and `TransportLimits`.
- `TransferAcl::parse_named` for the exemption list.

**Acceptance criteria:**
- [ ] With the limit at 2, a third connection from one peer is closed
      without a reply while two are open, and served once one closes.
- [ ] Two peers in one IPv6 /56 share a count; two in different /56s do not;
      two IPv4 addresses in one /24 do not.
- [ ] An exempt source and a limit of `0` are both unlimited.
- [ ] The table is empty after every connection closes (§5), checked by a
      test.
- [ ] One log line per source per minute however many refusals; the
      counter moves per refusal.
- [ ] Both daemons through `server_table!` (#103); tests and clippy on
      Windows and Linux; fmt, doc and the §12 grep clean.

**Out of scope:**
- Transactions per connection and connection duration
  (`.out-of-scope/connection-turnover-limits.md`).
- The query and response limiters' keying (#157).
- UDP.

**Closed 2026-10-03**, `0fd0a55`. The design as grilled. Where the brief
left a choice:

- The policy is `rdns_transport::SourceConnections` on `ServeContext`, not a
  parameter of the four serve functions: `tls::serve` and `https::serve` are
  at clippy's seven already, and the other per-source limits live there.
- The once-a-minute log limit is a timestamp on the source's table entry. A
  refused source always has one, so the limit on the log line needs no table
  of its own and inherits the entry's bound.
- The per-source check runs before the `PerConnection` rate charge, so a
  connection about to be closed costs its source no query token.
- DoQ refuses the `Incoming` before the handshake, as the rate refusal does.

`CLI_USAGE.md` had no entry for #155's two flags; it has one section for all
four now. Three of the four new tests fail with the check disabled; the
fourth is the off-switch test. 1418 tests on Windows, 1439 on Linux.
