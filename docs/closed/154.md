### 154. A cache entry's expiry has no type, and five caches write it by hand — **filed 2026-10-01, closed 2026-10-02**, **enhancement**, **ready-for-agent**

Every cache stores `expires_at: u64` and computes it, tests it and counts
down from it itself. Constructions: `cache.rs:364` saturates; the other seven
are plain `+` — `negative_cache.rs:185`, `nsec_cache.rs:219`, `:252`,
`:280`, `:381`, `:408`, `resolver/caches.rs:134`, `:280`. §2 and §6 say
`saturating_add` onto timestamps. Not a live overflow: `now` is
`SystemTime` seconds and every TTL is capped first, so it needs a clock near
`u64::MAX`, which only a `Clock::Fixed` can be. It is §17's shape — a rule
applied per call site, missed at seven of eight.

The reads are per site too: eleven `expires_at > now` liveness tests in
`negative_cache`, `nsec_cache` and `resolver/caches` against `cache.rs`'s
`now >= self.expires_at`, the same predicate spelled the other way; and
`expires_at.saturating_sub(now).min(u32::MAX as u64) as u32` four times
(`negative_cache.rs:86`, `nsec_cache.rs:100`, `:455`, `:507`).

**154a**, the same family: RFC 8767's stale-refresh claim —
`refreshing && now >= stale_refresh_after`, then push it one
`STALE_REFRESH_INTERVAL` on — is written in `cache.rs:311` and
`negative_cache.rs:332`, the second citing the first ("as the answer cache's
`get_stale` does").

Command for the constructions:
`grep -nE "expires_at: |expires_at = " rdns/src -r`, production code only.
No remedy costed.

**Triaged 2026-10-02**, confirmed by reading; the counts above hold. The
shape stops at the caches: the production `u64` fields that name a deadline
are `expires_at` (seven, in `cache`, `negative_cache`, `nsec_cache` and
`resolver/caches`) and `stale_refresh_after` (two). `learned_at`,
`signed_at`, `refreshed_at` and `taken_at` name instants already past and are
not this. Two readers take the raw `u64` and have to keep working:
`eviction::Halving` ranks by it and `StalePolicy::keeps` measures the stale
window from it. Each cache caps its TTL with its own constant before adding,
and the caps are per-cache policy. With `Clock::Fixed` near `u64::MAX` the
seven plain `+` overflow — a debug panic — so the fix has a test that can
fail first (§1), though production cannot reach it.

#### Agent brief

**Category:** enhancement
**Summary:** One cache-private deadline type for every cache entry's expiry
and stale-refresh moment.

**Current behavior:** five caches store `expires_at: u64` and write the
construction (`now + ttl`, saturating at one site of eight), the liveness test
(eleven `expires_at > now`, one `now >= expires_at` the other way round) and
the remaining time (four copies of `saturating_sub(now).min(u32::MAX as
u64) as u32`) themselves. The RFC 8767 stale-refresh claim is written in the
answer cache and copied into the negative cache.

**Desired behavior:** a `pub(crate)` type in `rdns`, beside `eviction`,
holding a deadline in Unix seconds:
- built from `now` and a number of seconds the caller has already capped,
  saturating;
- asked whether it is still live at `now`, meaning `now` is before it;
- asked how much is left at `now`, saturating, clamped to `u32`;
- ordered, so `Halving` can rank by it and `StalePolicy` can measure from it.

Every cache entry's `expires_at` is that type. The stale-refresh claim —
true when the caller is refreshing and the moment has come, moving the
moment one `STALE_REFRESH_INTERVAL` on — is one method in the same module,
used by both caches. No cache's behavior changes.

**Key interfaces:**
- `DnsCache`, `NegativeCache`, `NsecCache`, `DelegationCache`, `KeyCache`
  entries: `expires_at` changes type; their public methods do not.
- `eviction::Halving` and `StalePolicy::keeps`: take the new type, or a rank
  read from it, rather than a bare `u64`.
- The per-cache TTL caps (`MAX_PROOF_TTL`, `MAX_KEY_TTL`,
  `MAX_DELEGATION_TTL` and the rest) stay at their call sites.

**Acceptance criteria:**
- [ ] One test per cache inserts with `Clock::Fixed` near `u64::MAX` and
      reads the entry back; each is shown failing (a debug overflow panic)
      with the type reverted (§1).
- [ ] `grep` over production code finds no `expires_at` built with `+` or
      compared to `now` by hand, and no copy of the `u32` clamp outside the
      type.
- [ ] Both caches' stale-refresh tests pass unchanged; the claim is written
      once.
- [ ] `cargo test -p rdns --test allocations` and `rdnsr`'s allocation
      counts read the same before and after (§17: "measure it, do not
      assume it").
- [ ] Workspace tests and clippy pass on Windows and Linux; fmt and doc
      clean; the §12 grep prints nothing.

**Out of scope:**
- The TTL caps and their values.
- `learned_at` and the other recorded instants.
- RFC 5011's hold-down timers, the secondary's refresh timers, and anything
  else that is not a cache entry.

**Closed 2026-10-02**, `659ac8f`, 154a with it. `rdns::deadline::Deadline`
holds every cache entry's `expires_at` and `stale_refresh_after`; the
stale-refresh claim is `Deadline::claim_stale_refresh`, called by both
caches. `Halving` kept its `u64` rank, because the RTT map ranks by speed,
and is passed `unix_secs()`.

The five overflow tests: four panicked against the old code at the sites
this row named; `DnsCache`'s passed, `cache.rs:364` being the one that
already saturated. The stale-window test had to change, because `keeps`
now takes a `Deadline`; the two stale-refresh tests did not. Allocation
counts identical before and after in `rdns/tests/allocations.rs` and
`rdnsr`'s module. 1385 tests on Windows, 1406 on Linux.
