### 186. `rdnsr` counts no validation outcomes, and `dns_validation_errors_total` is not about DNSSEC — **filed 2026-10-06, closed 2026-10-07**, **bug**

Found triaging #172, which wanted a counter for answers from routed domains
with validation switched off and found no family for it to join.

- `rdnsr` counts nothing per `ValidationState`: Secure, Insecure, Bogus and
  Indeterminate answers are indistinguishable in a scrape. A Bogus answer is
  a `tracing::warn!` and a SERVFAIL (`rdnsr/src/answer.rs:391`), nothing an
  alert can watch. Checked: no `AtomicU64` in `DnsMetrics` names any of the
  four.
- `DnsMetrics::validation_errors`, exported as `dns_validation_errors_total`
  ("Validation errors"), is incremented only by `ServeContext::accept_packet`
  (`rdns-transport/src/lib.rs:252`): packets refused by the size and section
  caps. On a validating resolver an operator will read it as DNSSEC failures
  — `CLAUDE.md` §14, a counter's name is a claim about what it counts.

No remedy filed: whether to rename the existing series (a dashboard break)
or add a label, and which outcomes to count, is triage's call.

**Triaged 2026-10-06: bug, ready-for-agent.**

**Category:** bug
**Summary:** rename the series that claims to count validation errors to
what it counts, and add the DNSSEC validation-outcome counter it stood in
for.

**Current behavior:** `dns_validation_errors_total` is incremented only by
`ServeContext::accept_packet`, whose own doc comment says "Not validation —
a packet that passes is not known to be well formed". It counts packets
refused by the size and section caps, in both daemons. The field holding the
check is `ServeContext::validator`, of type `AdmissionCheck`. Separately,
`rdnsr` counts no `ValidationState` at all: a Bogus answer is a `warn!` and a
SERVFAIL, indistinguishable in a scrape from any other SERVFAIL.

**Desired behavior:**

- Rename `dns_validation_errors_total` to `dns_packets_rejected_total`, help
  text "Packets refused before parsing: size or section caps". Rename
  `DnsMetrics::validation_errors` and `ServeContext::validator` to match.
  Both daemons. No duplicate under the old name: one fact, one name. The
  commit message states the rename so dashboards can follow.
  `docs/spec/03` (§ near line 29) and `docs/spec/06` (the metric list) name
  the new series.
- New family, `rdnsr` only: `dns_validation_outcomes_total{outcome=...}`,
  `outcome` one of `secure`, `insecure`, `bogus`, `indeterminate` — four fixed
  values, so the label is bounded (§5).
- One increment per answer sent to a client by a validating `rdnsr`, by that
  answer's `ValidationState`, cache hits included. Prefetches, DNS64's A
  query and other internal resolutions are not counted: the question is
  what clients are getting.
- With validation off the family is not exported at all, rather than
  reporting every answer as indeterminate (§14: a gauge must be able to say
  "no answer", and absence is that).

**Acceptance criteria:**

- [ ] A packet over the section cap moves `dns_packets_rejected_total` in
      both daemons; `dns_validation_errors_total` appears nowhere in a
      scrape or the tree.
- [ ] Validating against signed mock zones: a secure, an insecure, a bogus
      and an unanchored answer each move their own `outcome` once.
- [ ] The same secure name answered again from cache moves `secure` again.
- [ ] A prefetch moves nothing.
- [ ] Validation off: no `dns_validation_outcomes_total` line in the scrape.
- [ ] Existing tests asserting on `validation_errors` are changed and named
      in the commit (§1).
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- A cause label for `indeterminate` (no anchor, routed domain with
  validation off, local zone, negative trust anchor).
- A breakdown of `bogus` by EDE code.
- Reshaping the RCODE series into a labelled family.

**Closed 2026-10-07**, `2c9a926`. As briefed, plus one change the brief did
not foresee: both caches stored `secure: bool`, so a cache hit could not say
whether it was insecure or indeterminate. `dnssec_chain::Outcome` replaced
the bool in `DnsCache` and `NegativeCache` (`CLAUDE.md` §17); AD is
`outcome.is_secure()`.

- Counted once per answer at the point the answer path holds an outcome:
  a resolution, a cache hit (the negative and RFC 8198 arms included, the
  latter as secure), a stale answer, and the bogus SERVFAIL. Not counted:
  special-use names and empty zones, policy rewrites decided before
  resolution, and failures with no validation state.
- A Bogus answer served to a CD client is counted bogus.
- The insecure case in the test is seeded into the cache rather than
  resolved: the signed fixture has no unsigned delegation whose missing DS
  could be proved.
