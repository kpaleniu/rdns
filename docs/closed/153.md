#### Agent brief

**Category:** enhancement
**Summary:** One configured-then-bound value in `rdns-transport` for the
encrypted listeners, used by both daemons.

**Current behavior:** each daemon checks that DoT, DoQ or DoH has a
certificate pair, loads a `CertificateStore`, binds each configured encrypted
listener, and spawns them with plain TCP into its `JoinSet`, in its own
copy. `rdnsd` holds the configured half as `TlsPolicy` with
`describe_encrypted`; `rdnsr` uses its `Cli` fields directly, checks the pair
rule twice and never names its listeners.

**Desired behavior:** two values in `rdns-transport`.
- **Configured:** built from the merged view — the three optional
  addresses, the DoH path, the certificate and key paths, and optional
  client anchors (`rdnsd`'s `--transfer-client-ca`; `None` for `rdnsr`).
  Building it checks the pair rule once, with the wording "tls-listen,
  quic-listen and https-listen need both tls-cert and tls-key", and loads the
  store. It describes itself for the startup line and `--check-config`, and
  hands its store to the daemon's reload path. Built above the dry-run exit
  and binds nothing.
- **Bound:** made from the configured value after the dry-run exit; binding
  failures name the flag as today. Given the already-bound plain TCP
  listener, a handler, a `RateLimit`, a `TransportLimits` and the lifecycle
  (`Stop`, `Busy`), it spawns TCP and every configured encrypted transport
  into the caller's `JoinSet`.

Both daemons use them; `TlsPolicy` and `describe_encrypted` go into the
configured value. UDP, metrics and control stay where they are.

**Key interfaces:**
- The configured value's constructor returns `anyhow::Result`; the pair-rule
  error is its only new failure.
- The store stays one `Arc<CertificateStore>` shared by every encrypted
  listener and the reload path (#42a).
- `TransportLimits` is a parameter, not `default()` inside, so #155 has one
  place to change.

**Acceptance criteria:**
- [ ] Commit 1: `rdnsd` uses the shared pair with no output change;
      `rdnsd/tests/startup.rs` passes unmodified.
- [ ] Commit 2: `rdnsr` uses it; its file-level pair check and its own
      `main` check are gone, and the test that covered the file check covers
      the shared constructor instead. Its startup line and `--check-config`
      name each configured encrypted listener as `rdnsd`'s do, and the
      commit says the output changed.
- [ ] A test of `--check-config` on `rdnsr` with only DoH configured shows
      the DoH address — the case `describe_encrypted`'s history is about.
- [ ] No `TcpListener::bind` or `quinn::Endpoint::server` for an encrypted
      listener remains in either daemon.
- [ ] Workspace tests and clippy pass on Windows and Linux (the control
      socket path is `cfg(unix)`, §1); fmt and doc clean; the §12 grep
      prints nothing.
- [ ] Commit 3 files nothing new (#155 is filed) and closes #153.

**Out of scope:**
- The UDP loops (#30), the metrics and control listeners.
- `TransportLimits`' values or flags (#155).
- Certificate reload behavior.

**Closed 2026-10-02**, `34bfceb` (`rdnsd`) and `2e248e5` (`rdnsr`).
`rdns_transport::encrypted` holds `Encrypted` (configured: the pair rule
once, the store, the client anchors, `listeners()` and `describe()` for the
two output lines) and `EncryptedListeners` (bound; `spawn` puts plain TCP
and every encrypted listener into the caller's `JoinSet`). `TlsPolicy` and
`describe_encrypted` went into the first.

Two places the brief's shape moved:

- `TransportLimits` is a parameter of `bind`, not of `spawn`. DoQ's stream
  and idle ceilings are transport parameters fixed when its endpoint is
  built, so the limits have to be in hand at bind; `spawn` uses the same
  value for all four loops. #155 still has one place to change per daemon.
- `rdnsd` reads `--transfer-client-ca`'s anchors before configuring the
  listeners, since they are built with them. The check that refuses anchors
  without a listener stayed where it was. Only the order of two errors in
  one misconfiguration can differ.

`rdnsd`'s output did not change and `rdnsd/tests/startup.rs` passed
unmodified. `rdnsr`'s did: its pair-rule message is `rdnsd`'s, its startup
line names the encrypted listeners, and `--check-config` names them, which
`the_dry_run_names_a_doh_only_listener` covers and which fails against
`34bfceb`. 1389 tests on Windows, 1410 on Linux.
