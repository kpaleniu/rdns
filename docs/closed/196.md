### 196. Raw control bytes in two test literals — **filed 2026-10-08, closed 2026-10-09**

Found in review. Two byte-string literals hold literal control octets where
escapes were meant:

| site | bytes | should read |
|---|---|---|
| `rdns-transport/src/dnstap.rs:457` | NUL NUL NUL BEL | `b"\x00\x00\x00\x07payload"` |
| `rdns-core/src/lib.rs:700` | STX | `b"\x02to"` |

Both compile and pass. The NUL makes `grep` treat `dnstap.rs` as binary: it
prints `Binary file ... matches` instead of the lines, so a `grep` count of a
shape — the method §18 and §19 rest on — silently skips the file. `lib.rs`
greps normally; the STX is just invisible in an editor and a diff.

Counted over every tracked `.rs`, `.md`, `.toml`, `.sh`, `.yml`, `.py` and
`.txt` file for octets 0x00-0x08, 0x0b, 0x0c, 0x0e-0x1f and 0x7f: these two
lines and no others.

Not decided: whether a check belongs beside §12's double-encoding `grep`.

## Closing note (2026-10-09)

Both literals now spell their bytes as escapes; the byte strings are
unchanged, and `rdns-core` and `rdns-transport` pass on Windows.

The undecided question is decided: the check belongs beside §12's
double-encoding one, because both catch what a script edit can introduce
without a diff showing it. `CLAUDE.md` §12 now carries

```sh
git grep -naP '[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]' -- '*.rs' '*.md' '*.toml' '*.sh' '*.yml' '*.py' '*.txt'
```

`-a` because the defect is what makes a file read as binary; without it the
check skips exactly the file it is for. It printed these two lines before the
fix and nothing after, which is the whole tree.
