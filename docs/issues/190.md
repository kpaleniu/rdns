### 190. Neither daemon can run as a Windows service — **filed 2026-10-07**, **needs-triage**

Split from #188, which gives Windows a control channel; starting and stopping
under the Service Control Manager is a separate question.

What exists: `rdns::shutdown` stops cleanly on the console events —
`ctrl_c`, `ctrl_break`, `ctrl_close`, `ctrl_shutdown` (the Windows half of
`rdns/src/shutdown.rs`,
`CLAUDE.md` §4's account of why all four are needed). Searched: no service
dispatcher, no `SERVICE_` handling, no `windows-service` crate in the tree.

Not checked, and each needs checking before a remedy is named (§18, §19):
whether `sc.exe create` on either binary starts at all without a dispatcher;
what a service wrapper (NSSM, WinSW) sends on stop and whether the handlers
above catch it; whether `windows-service` or `windows-sys` is the cheaper
route, given that `windows-sys` is already in `Cargo.lock` and the tree has no
`unsafe` outside test allocators.
