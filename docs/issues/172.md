### 172. `rdnsr` cannot forward one domain and recurse the rest — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

Unbound's `forward-zone`/`stub-zone`, BIND's per-zone `forwarders` and
`type stub`, and PowerDNS Recursor's `forward-zones` all route a subtree to
named servers. The usual case is an internal domain served by the corporate
or AD servers, everything else recursed.

`ResolverMode { Recurse, Forward }` (`rdns/src/resolver.rs:289`) carries one
global `upstream_servers` (`:303`); any `--upstream` or `upstream =` switches
the whole resolver (`rdnsr/src/main.rs:673-675`, `rdnsr/src/config.rs:93`).
The doc comments at `main.rs:186` and `:206` liken that global switch to
`forwarders`/`forward-zone`, which overstates it: `forward-zone` is per
domain.

Searched, nothing found: `forward.?zone`, `stub.?zone`, `conditional`,
`ForwardZone`, `StubZone`, `domain_upstream` beyond those two comments. Not a
recorded decision.

Related: #173, which blocks the reverse half of the same deployment.

## Agent brief

> *This was generated by AI during triage.*

**Triaged 2026-10-06: enhancement, ready-for-agent.** Terms in `CONTEXT.md`:
**Routed domain**, **Forward zone**, **Stub zone**.

**Category:** enhancement
**Summary:** route a subtree to named servers — forwarded or walked from —
and make global forwarding the case where that subtree is the root.

**Current behavior:** `ResolverMode { Recurse, Forward }` is one switch for
the whole resolver, branched on twice (`resolve_untimed`, `fetch_dnskeys`).
Any `--upstream` forwards every name; nothing can send one domain elsewhere.
Two doc comments on `rdnsr`'s `--upstream` liken it to BIND's
`forwarders`/Unbound's `forward-zone`, which are per domain.

**Desired behavior:**

- A table of routed domains, each a forward zone (asked with RD=1, as
  `forward` does today) or a stub zone (the delegation walk started at the
  domain with the named servers, RD=0). `--upstream X` is a forward zone at
  `.`; `ResolverMode` and both branches on it go.
- Routing happens where every lookup passes — today `resolve_from_root` — so
  CNAME hops, nested nameserver-address lookups and validation's DNSKEY and
  DS fetches are routed too. The most specific routed domain covering the
  name wins, and beats any cached delegation at or above it; delegations
  cached *below* a stub zone are used as usual.
- Forwarded answers now pass the same chain filter and DNAME synthesis as
  recursed ones. Stricter than today: records a forwarder volunteers for
  names off the chain are no longer cached. Existing forwarding tests must
  still pass; any that change are named in the commit (§1).
- Validation applies by default. `validate = false` on a routed domain makes
  its answers `ValidationState::Indeterminate`, reason naming the domain,
  served without AD — not `Insecure`, which means *proven* unsigned. The
  usual case needs it: a private `corp.example.com` under a signed
  `example.com` is provably absent from the public tree. #176's negative
  trust anchors should reuse this mechanism, not add a second.
- No fallback to recursion when a routed domain's servers fail: SERVFAIL
  with EDE "No Reachable Authority". Falling back leaks internal names
  upstream and caches public NXDOMAIN over the subtree (RFC 8020).
- The RPZ nameserver policy is asked about a routed domain's servers at
  entry, as for a walk started from a cached delegation (#56).
- A routed domain at or under a built-in RFC 6303 zone overrides the built-in
  answer for its subtree (#173 decides the rest).
- Transport: UDP with TCP fallback, as every upstream query today. Leave the
  routing type room for a transport (#175) without adding one.
- The startup banner lists each routed domain: kind, servers, validated or
  not. It replaces the "forwarding to …" line.

**Key interfaces:**

- Flags, repeatable: `--forward-zone NAME=ADDR[,ADDR…]`,
  `--stub-zone NAME=ADDR[,ADDR…]`, `--no-validate-zone NAME`. `ADDR` is
  `ip` or `ip:port` (`[v6]:port`), port 53 by default.
- Config: `[[forward-zone]]` and `[[stub-zone]]` tables with `name`,
  `servers`, `validate` (default true), `deny_unknown_fields`.
- Refused at startup, naming the entry, before `--check-config` returns
  (§15): a name that does not parse; one name configured twice or as both
  kinds; an empty server list; `--no-validate-zone` naming no routed domain;
  `--upstream` with a forward zone at `.`; `--root-hints` with `.` forwarded
  (today a warning).

**Acceptance criteria:**

- [ ] With `--forward-zone corp.test=<mock>`, a `corp.test` name is asked of
      the mock with RD=1 and a public name is recursed; the mock sees no
      public query and the root mock sees no `corp.test` query.
- [ ] With `--stub-zone`, the mock is asked with RD=0 and a referral it
      returns below the stub zone is followed.
- [ ] A CNAME from a public name into a routed domain, and out of one, is
      resolved through the right servers at each hop.
- [ ] A routed domain whose nameserver names lie inside it resolves.
- [ ] Nested routed domains: the deeper one wins.
- [ ] A routed domain overrides a cached delegation for its parent.
- [ ] Validating, a routed domain with no public delegation under a signed
      parent: Bogus with `validate = true`, Indeterminate and answered
      without AD with `validate = false`.
- [ ] Routed domain servers unreachable: SERVFAIL with EDE 22, and no
      query reaches the root mock.
- [ ] `--upstream` alone behaves as before, with the stricter filtering;
      `ResolverMode` no longer exists.
- [ ] A routed domain under `10.in-addr.arpa.` is answered from its servers,
      not the built-in NXDOMAIN.
- [ ] Each startup refusal above has a test, including under `--check-config`.
- [ ] Flag and config produce the same table; both together is refused.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- Encrypted transport to routed domains (#175).
- Forward-first fallback.
- Per-domain counters, or validation-outcome counters (#186).
- Negative trust anchors (#176), beyond not blocking their reuse of
  `validate = false`.
- Re-reading routed domains on SIGHUP.
