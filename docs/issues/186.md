### 186. `rdnsr` counts no validation outcomes, and `dns_validation_errors_total` is not about DNSSEC — **filed 2026-10-06**, **needs-triage**

Found triaging #172, which wanted a counter for answers from routed domains
with validation switched off and found no family for it to join.

- `rdnsr` counts nothing per `ValidationState`: Secure, Insecure, Bogus and
  Indeterminate answers are indistinguishable in a scrape. A Bogus answer is
  a `tracing::warn!` and a SERVFAIL (`rdnsr/src/answer.rs:391`), nothing an
  alert can watch. Checked: no `AtomicU64` in `DnsMetrics` names any of the
  four.
- `DnsMetrics::validation_errors`, exported as `dns_validation_errors_total`
  ("Validation errors"), is incremented only by `ServeContext::accept_packet`
  (`rdns-transport/src/lib.rs:252`): packets refused by the size and section
  caps. On a validating resolver an operator will read it as DNSSEC failures
  — `CLAUDE.md` §14, a counter's name is a claim about what it counts.

No remedy filed: whether to rename the existing series (a dashboard break)
or add a label, and which outcomes to count, is triage's call.
