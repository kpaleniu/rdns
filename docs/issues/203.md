### 203. No performance pipeline: a throughput regression fails nothing — **filed 2026-10-10**, **enhancement**, **needs-triage**

CI gates the deterministic half: exact allocation counts
(`rdns/tests/allocations.rs`) and each criterion bench run once in test mode
(`cargo test -p rdns --benches`, 14 `bench_function`s in
`rdns/benches/answer_path.rs`). Nothing compares timings between commits, and
the dnsperf measurements in #185 were taken by hand.

Wanted: a `workflow_dispatch` workflow measuring a base ref and a head ref
and reporting the difference.

Constraint from #185: throughput drifted 10-25% between server starts on one
VM, and a single-run comparison produced a false finding (185b's 745k).
Base and head must be alternated within one job, several runs each. Hosted
runners are shared VMs; their noise is unmeasured, so whether the result can
gate or only report is open until it is.

For triage: criterion only, dnsperf against `rdnsd` as well (package on the
runner unchecked), or both.
