### 206. Whether `perf.yml` can gate, or only report — **filed 2026-10-10**, **enhancement**, **needs-info**

Deferred by #203's triage: `perf.yml` reports and never fails on a measured
difference, until the noise of a hosted runner is known.

What is known, from one A/A run on the development machine (Linux under WSL,
5aa1b76, `tools/perf_compare.py HEAD HEAD`):

- dnsperf medians head/base 1.003; per-side ranges about 1.6% and 3.7%.
- criterion, 15 benches: changes from -5.8% to +1.5% for an identical binary,
  5 with a 95% interval excluding zero. Criterion's own "significant" is not
  a usable gate here.

Needed: several bare dispatches of `perf.yml` (each an A/A run on a hosted
2-vCPU runner), their spreads, and then a threshold that none of them crosses
but a known regression does. Dispatching costs Actions minutes, so the runs
are the owner's call.

2026-10-11: no dispatch is possible yet. `gh run list --workflow perf.yml`
answers 404, "workflow perf.yml not found on the default branch": the
workflow exists only in commits not yet pushed. A push comes first, and both
are the owner's call.
