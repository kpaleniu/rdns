### 171. `rdnsr` has no client access control: bound off localhost, it is an open resolver — **filed 2026-10-05**, **bug**, **ready-for-agent**

Found comparing against BIND, Knot, Unbound and PowerDNS. Unbound has
`access-control`, BIND `allow-query`/`allow-recursion`; both default to
refusing non-local clients.

Nothing in `rdnsr` refuses a source by address. On a UDP datagram it runs
`allow_source` (the rate limiter, `rdns-transport/src/lib.rs:213`),
`accept_packet` (size and section caps, `lib.rs:236`) and the in-flight
shedding (`rdnsr/src/serve.rs:65-77`); `handle_query`
(`rdnsr/src/answer.rs:105`) checks the source only for NOTIFY. The sole
protection is the default `--host 127.0.0.1` (`rdnsr/src/main.rs:106`), and
binding anything else prints no warning.

Searched, nothing found: `allow[-_]?(query|recursion)`, `access[-_]?control`,
`allow_from`, `deny_from`, `client[-_]?acl`, `QueryAcl`, `RecursionAcl` over
`rdnsr/src`, `rdns/src`, `rdns-transport/src`, `docs/`. Not a recorded
decision: absent from `docs/closed/021.md`, `docs/closed/045.md` and the ADRs.

`--query-rate-exempt` is an exemption from the limiter, not an ACL
(`RateLimitConfig::exempting`, `main.rs:947`).

**Workaround today:** an `rpz-client-ip` trigger at `0.0.0.0/0` (and `::/0`)
with `CNAME rpz-drop.`, plus `rpz-passthru.` for allowed prefixes — longest
prefix wins (`rdns/src/rpz.rs:265`) and client-ip is checked before the qname
(`rpz.rs:966`). It does not cover `special_names`, which answers first
(`answer.rs:244`), it still completes TCP, DoT, DoH and DoQ handshakes, and
nothing documents it as an ACL.

`security::TransferAcl` already parses addresses and CIDR prefixes for
`--allow-transfer` and `--query-rate-exempt` (`CLAUDE.md` §7).

**Triaged 2026-10-06: bug, ready-for-agent.** Decisions in ADR 0007 and
`CONTEXT.md` (**Allowed client**).

**Category:** bug
**Summary:** give `rdnsr` a query ACL, and refuse to start off loopback
without one.

**Current behavior:** any peer that reaches a listener is resolved for. The
only protection is the default bind to `127.0.0.1`; binding elsewhere is an
open resolver with no warning.

**Desired behavior:**

- `--allow-query <addr|prefix>`, repeatable, and `allow-query = [...]` in
  `rdnsr`'s own `[server]` keys (not `rdns::server_table!`, which `rdnsd`
  shares). Parsed by `TransferAcl::parse_named(…, "query ACL")`, so a typo
  fails startup and families match as #158 settled.
- Startup refuses, naming the flag, when any listener — `--host`,
  `--tls-listen`, `--quic-listen`, `--https-listen` — binds outside
  `127.0.0.0/8` and `::1` and no list is given. `0.0.0.0` and `::` are off
  loopback. Once a list is given nothing is allowed implicitly, loopback
  included.
- Startup refuses, naming both rules, when an `--rpz-notify-from` rule is not
  wholly inside some `--allow-query` rule: the ACL runs before NOTIFY is
  parsed, so an unlisted primary's NOTIFY would be refused silently.
- Both startup checks run before `--check-config` returns (`CLAUDE.md` §15).
- UDP: the ACL is the first check, before `allow_source`, so a refused peer
  never gets a rate-limiter entry (§5). Its packet still passes
  `accept_packet` and `validation::Request` — a QR=1 datagram gets nothing
  (§8) — and is answered REFUSED with the question echoed, the client's OPT
  mirrored, and EDE 18 (Prohibited, RFC 8914 §4.19) when it sent EDNS. The
  reply goes through the response budget like any other.
- Stream listeners (TCP, DoT, DoH, DoQ): a refused peer is closed at the
  shared connection admission, beside the per-source limit, before any TLS or
  QUIC handshake.
- DoH matches the TCP peer only; no `Forwarded` / `X-Forwarded-For`.
- Counted: one UDP refusal counter, and a per-listener stream counter beside
  `refused_per_source`. The startup banner prints the list, or that the
  resolver is open on loopback only.
- Read once at startup. SIGHUP reloads only certificates and RPZ, and stays so.

**Key interfaces:**

- `QueryAcl { Open, Only(TransferAcl) }` in `rdns-transport`, held by
  `ServeContext`. `rdnsd` constructs `Open`. Not `Option<TransferAcl>`: an
  empty `TransferAcl` means nobody, and `None` would mean the opposite (§17).
- `TransferAcl` gains a prefix-containment test for the `--rpz-notify-from`
  check.

**Acceptance criteria:**

- [ ] UDP query from an unlisted peer: REFUSED, question echoed, EDE 18 when
      the query carried OPT; no limiter entry is created for that peer.
- [ ] UDP datagram with QR=1 from an unlisted peer: no reply.
- [ ] TCP and DoT connection from an unlisted peer: closed with no bytes read
      and no handshake started; the per-listener counter moves.
- [ ] IPv4 client on a `::` bind is matched by an IPv4 rule (ADR 0006).
- [ ] Listed peer: answered exactly as today.
- [ ] Startup and `--check-config` fail off loopback with no list, and for an
      `--rpz-notify-from` rule outside the list; both messages name the flag
      or rules. Loopback binds with no list start as today.
- [ ] Config file and flag both reach the same `QueryAcl`; flag plus file is
      refused like every other setting.
- [ ] Each regression test shown failing against the old code (§1).
- [ ] `cargo test`, `cargo clippy --all-targets` and `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- A query ACL for `rdnsd`.
- Separate query and recursion lists (BIND's pair): `rdnsr` only recurses.
- Trusted-proxy handling for DoH.
- Re-reading the list on SIGHUP.
- Renaming `TransferAcl`, though it now holds four kinds of list.
- Documenting the RPZ client-ip workaround.
