Not every reference is history. A pointer to an *open* item, naming a known
limitation, is current. A closed item cited as the reason for the code is
history: the reason should be stated in the comment, and the number belongs
in the commit that made the change.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Make every comment in the Rust tree describe the code as it is,
following "Writing comments" in `CLAUDE.md`.

**Current behavior:**
Comments narrate how the code got here ("used to", "until #N", "watched
failing against"), keep struck-through claims, and cite closed items as
"see also" whether or not the item holds anything a reader needs. Counts in
this file's tables.

**Desired behavior:**
- No comment line in a `.rs` file contains history: what the code used to do,
  which bug or item led to it, when it changed, what was watched failing.
  Each such sentence is deleted, or rewritten as the present-tense reason it
  stood in for. The history is left to the commit that made the change.
- No `~~` in a `.rs` file. A struck claim goes; its correction stays, in the
  present tense.
- Test doc comments say what the test checks: "Fails if …".
- `` `TODO.md` #N `` to a closed item remains only where #N is classified
  **reference**. Pointers to open items are untouched. `CLAUDE.md §N` and RFC
  citations are untouched.
- Comment length is not changed except where removing history shortens it.

**Key interfaces:**
- "Writing comments" in `CLAUDE.md`: the rule and its bad/good example.
- `docs/closed/NNN.md`: the source for each reference/landing verdict.

**Acceptance criteria:**
