### 197. Comments narrate history — **filed 2026-10-08**, **needs-triage**

Found in review. `CLAUDE.md` §11 now says a comment states why the code is
the way it is now, and the history belongs in the commit message. The tree
does not follow it. Measured over `rdns*/` `.rs` files:

Typical shape: `answer_admitted`'s comment lists three past bugs before it
says what the function does. The cost showed in #195, where a four-line race
sat under comments asserting the serialization held.

Not every reference is history. A pointer to an *open* item, naming a known
limitation, is current. A closed item cited as the reason for the code is
history: the reason should be stated in the comment, and the number belongs
in the commit that made the change.

Not decided: whether this is one reformat-style sweep (its own commit, in
`.git-blame-ignore-revs` per §12, so blame skips it), or a rule applied per
file as each is next touched. Strike-throughs in Rust comments go either way:
§11's rule for struck claims is about `TODO.md` and issue files, which keep
their reasoning in place because they have no commit message of their own;
code has one.
