### 211. Wall-clock ratio tests fail under CPU contention — **filed 2026-10-11**, **bug**, **needs-triage**

Found while working #207. Two of the eleven tests that call
`testutil::fastest_of_each` failed under load on Linux (WSL, Fedora 44), with
16 busy loops on 16 CPUs:

- `zone::tests::parsing_does_not_cost_more_per_record_when_every_record_moves_the_origin`,
  1 failure in 20 loaded `cargo test --workspace` runs: 3.69x against 3.
  Fixed with `rpz.rs:1305`, the same shape, in `a38f2e9`.
- `rpz::tests::a_query_costs_the_same_however_many_address_rules_the_feed_holds`
  (`rpz.rs:1374`), 1 failure in 50 loaded runs of the `rdns` lib binary:
  107 ns at 1k rules against 462 ns at 10k, 4.3x against 4. Open.

The remaining nine compare two sizes where the expected ratio is about 1,
and the bug they guard is the size ratio:

| site | sizes | limit | bug's ratio |
|---|---|---|---|
| `rdns/src/rpz.rs:1374` | 1k, 10k rules | 4 | 10 |
| `rdnsd/src/zones.rs:1917` | `SMALL`, `LARGE` RRsets | 1.5 | not read |
| `rdns/src/nsec_cache.rs:1092` | 8, `MAX_PROOFS_PER_ZONE` | 3 | not read |
| `rdns/src/negative_cache.rs:1082` | bound x4, bound | 3 | not read |
| `rdns/src/resolver/caches.rs:558` | bound x4, bound | 3 | not read |
| `rdns/src/logging.rs:608` | 0, `depth` queries | 5 | not read |
| `rdns-core/src/compression.rs:286` | 25, 800 names | 5 | 32 |
| `rdnsd/src/zones.rs:1853` | 1, 1000 zones | 10 | 1000 |
| `rdnsd/src/zones.rs:1875` | 3, 34 labels | 10 | not read |

Not measured: each test's ratio under load. The method used for the two
fixed tests: print the ratio, run the binary 40 times under load beside the
widened version, and compare min, median and max with the limit (`a38f2e9`).

`rpz.rs:1374` times a 1.4 ms batch. Its large side's index is ten times the
working set, so contention may cost it more cache than the small side. That
is a reading, not a measurement. §10 prefers a deterministic count: nodes
visited per lookup, if the index can report it.
