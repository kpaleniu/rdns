### 183. Signing with an imported RSA key is implemented and never tested — **filed 2026-10-05**, **ready-for-agent**

`ring` cannot generate RSA keys, so generation is refused and points at
openssl (`rdns/src/dnssec_key.rs:350-356`). Import (`RsaKeyPair::from_pkcs8`,
`:412-416`) and signing (`Pair::Rsa`, PKCS#1 SHA-256/512, `:582-592`) exist.
No test signs with an RSA key and no RSA PKCS#8 fixture is in the tree; the
RSA tests are the generation refusal and the RFC 3110 public-key layout
(`:1179`, `:1205`, `:1216`).

`CLAUDE.md` §1 and spec/07 G-4 are this shape: a tested-looking feature no
test reaches. RSA/SHA-256 is still the most deployed algorithm, so a signer
that has to import one is the ordinary case for a migrated zone.

**Brief:** a 2048-bit PKCS#8 fixture generated once with openssl and checked
in under the test fixtures; sign a small zone with it at algorithm 8 and 10;
judge the result with `verify_rrset` and with dnspython's
`dns.dnssec.validate` (recipe in `TODO.md`). Show the test failing by
breaking the signing call.
