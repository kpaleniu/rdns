### 205. Mutation testing with `cargo-mutants` — **filed 2026-10-10**, **enhancement**, **triaged 2026-10-10**, **ready-for-agent**

`CLAUDE.md` §1 asks whether a test is evidence; nothing measures it.
`cargo-mutants` is not used. The suite is 1,607 passing tests in about 29 s
warm on Windows; the mutant count, and so the cost of a full run, is not
measured: `cargo mutants --list | wc -l` is the first step.

Wanted: a `workflow_dispatch` workflow running `cargo mutants`, with an input
selecting a crate or a diff (`--in-diff`), uploading `mutants.out/`.
Surviving mutants are findings, filed per crate.

For triage: shard across jobs (`--shard`) if a full run outgrows one job;
which crates first (`rdns-core` holds the wire parsing).

## Triage decisions (2026-10-10)

- Measured 2026-10-10, cargo-mutants 27.1.0: 7,470 mutants (`rdns` 3,976,
  `rdns-core` 1,270, `rdnsd` 723, `rdnsr` 395, `rdns-transport` 376,
  `rdns-present` 335, `rdns-tsig` 335, `rdnsc` 43, `rdnsctl` 17). A sample on
  Windows, warm: `rdns-core` about 2 s per mutant, `rdns` about 10 s with a
  32 s baseline. `rdns` alone is about 11 h there; a hosted runner is slower
  (unmeasured). A whole-workspace run exceeds a 6 h job and most of a month's
  free-tier minutes.
- Already missed in the sample: `current_unix_timestamp` replaced with `1`
  (`rdns-core`, `clock.rs`) and `StalePolicy::is_on` replaced with `true`
  (`rdns`, `cache.rs`). Filed when this is worked, not here.
- Default mode `--in-diff` against a `base` input. Alternative: a `package`
  input with a `shards` input (default 1), one job per shard. No
  whole-workspace option.
- Linux only. 350-minute job timeout and cargo-mutants' per-mutant timeout,
  so an oversized run stops visibly before the 6 h kill.
- Report only; survivors filed by hand. The run fails only if the unmutated
  baseline fails.

## Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Run cargo-mutants on a diff or one sharded crate from a manually
dispatched workflow.

**Current behavior:** cargo-mutants is not used. Nothing measures whether
the suite catches a changed behaviour.

**Desired behavior:**
- A `workflow_dispatch` workflow on `ubuntu-latest` with inputs `base`
  (default `main`), `package` (default empty) and `shards` (default 1).
- `package` empty: mutants in `git diff base...HEAD` only (`--in-diff`).
  `package` set: `-p <package>` split over `shards` jobs (`--shard k/n`).
- `mutants.out/` uploaded per job; the job summary lists missed and timed-out
  mutants per file.
- Job timeout 350 minutes. The run fails only on a baseline failure or an
  infrastructure error, never on a missed mutant.
- A `.cargo/mutants.toml` only where an exclusion is needed, each excluded
  pattern with its reason.

**Acceptance criteria:**
- [ ] The diff mode runs locally on Linux against a one-function change and
      reports its mutants, platform stated.
- [ ] `-p rdnsctl --shard 0/2` and `1/2` together cover what `-p rdnsctl`
      does (17 mutants).
- [ ] The workflow parses (`actionlint`, or the reason it cannot run).

**Out of scope:** killing the survivors; whole-workspace runs; Windows.
