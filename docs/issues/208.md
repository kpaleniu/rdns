### 208. Tests wait by sleeping — **filed 2026-10-10**, **enhancement**, **triaged 2026-10-10**, **ready-for-agent**

`git grep` for `thread::sleep`, `time::sleep(` and `sleep_until` in `*.rs`
outside `fuzz/`: 51 sites. 12 in production code, 38 in tests, 1 in an
example (`udp_flood`'s run length). Each test site read in context:

| class | sites | what the sleep does |
|---|---|---|
| A. paused clock | 10 | virtual time under `start_paused`; deterministic and instant |
| B. poll until a condition, with a deadline | 14 | wait for a counter, a gauge, a file or a socket to change |
| C. fixed wait, assumed long enough | 5 | "long enough for the loop to have taken all four" |
| D. real time is the subject, or a fake peer is slow | 9 | idle and keepalive timeouts, a 1.8 s bound, a slow reader |

- A: `resolver.rs` 3, `rdnsd/src/main.rs` 3, `replication.rs` 2,
  `rpz_transfer.rs` 1, `secondary.rs` 1 (`pass`, called only from paused
  tests).
- B: `dnstap.rs:412`, `quic.rs:567`, `tcp.rs:717`, `tcp.rs:789`,
  `tls.rs:800`, `prefetch.rs:160`, `tap.rs:213`, `dispatch.rs:3396`,
  `:3583`, `:3600`; `rdnsd/tests/startup.rs:358`, `:497`, `:639`, `:868`,
  which poll a child process.
- C: `control.rs:468` (200 ms), `serve.rs:272` (200 ms), `flood.rs:141`
  (3 s), `:164`, `:166`. A slow machine turns these into wrong answers in
  either direction: a pass that checked nothing, or a failure.
- D: the slow-peer handlers in `https.rs:468`, `quic.rs:466`, `tcp.rs:414`,
  `flood.rs:83`; `quic.rs:1019`, `tcp.rs:962`, `dot.rs:819`, `answer.rs:3131`,
  `shutdown.rs:288`. Real sockets, so tokio's paused clock does not apply as
  is: it auto-advances whenever every task is blocked, I/O included.

Production, for completeness: 10 are timers in a `select!` (idle timeouts,
SOA refresh, probes, maintenance), where the elapsed time is the event. Two
are retries: `rdns-transport` backs off after an accept error, and `rdnsctl`
retries `ERROR_PIPE_BUSY` every 20 ms, up to 50 times.

Not known: whether any of class C is #207's unidentified failure. Wall time
spent in these sleeps per test run is not measured.

## Triage decisions (2026-10-10)

- Class C: wait for the event itself (await the operation, a channel, a
  `Notify` the code already has); where none exists, a class-B poll of the
  asserted condition. None stays a fixed wait.
- Class B, in process: restructure the test to await what it waits for;
  failing that, a test-visible signal beside the metric, fired where the fact
  changes; failing that, the shared `eventually` helper.
- `eventually(deadline, condition)` lives in `rdns::test_util` behind a new
  `test-util` feature, enabled by the other crates in `[dev-dependencies]`
  only. One copy (§7).
- `rdnsd/tests/startup.rs` keeps polling: across a process boundary that is
  what an operator does too.
- Class D stays: real time or real sockets are the subject.
- Production: the `select!` timers and the accept backoff stay. `rdnsctl`'s
  `ERROR_PIPE_BUSY` retry stays too: `WaitNamedPipeW` would be the tree's
  first production `unsafe` (`rdns-transport/Cargo.toml` says so), against a
  bounded 1 s wait that only happens when every instance is taken.
- `clippy.toml` `disallowed-methods` for `std::thread::sleep`,
  `tokio::time::sleep` and `tokio::time::sleep_until`. Every kept site
  carries `#[expect(clippy::disallowed_methods, reason = "...")]`; paused-clock
  sites say so.
- Done means cargo-mutants results can be trusted (the owner's goal). A sleep
  harms them three ways: it inflates the baseline every per-mutant timeout is
  derived from; a fixed wait or a flake fails for reasons other than the
  mutant, a false "caught" that differs run to run; a poll that never ends is
  a "timeout", not a failed assertion. Measured before and after.

## Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Replace test sleeps that wait for an event with the event, put
every remaining sleep behind a stated `#[expect]`, and show cargo-mutants
gives repeatable verdicts.

**Current behavior:** 51 sleeps (table above). 5 tests wait a fixed time and
assume it was enough; 14 poll; each crate writes its own polling loop.
Nothing stops a new sleep.

**Desired behavior:**
- Every class-C site waits on its event or polls its asserted condition
  with a deadline; no fixed wait remains in a test.
- Every in-process class-B site awaits the operation or a signal where it
  can; the rest call `rdns::test_util::eventually`.
- `clippy.toml` disallows the three sleep functions; each surviving call has
  an `#[expect]` with a reason, including the 12 production sites, the
  paused-clock tests and `udp_flood`.
- Any signal added for a test is fired where the fact changes (§14), and
  costs nothing measurable on the query path (`allocations` unchanged).

**Acceptance criteria:**
- [ ] cargo-mutants over a fixed sample, `-p rdns-transport --shard 0/4` and
      `-p rdnsr --shard 0/4` with `--test-workspace=false` (the sleeping
      tests live in those crates), run twice before the change and twice
      after, on Linux. After: both runs' caught/missed/timeout/unviable lists
      are identical. Before: recorded, identical or not, so the comparison
      can refute the premise. Mean time per mutant and the timeout count,
      before and after, in the commit.
- [ ] Each converted class-C site shown failing when its event is
      suppressed: the test fails at its deadline instead of passing.
- [ ] `cargo test --workspace --no-fail-fast` 20 times on Linux and 5 on
      Windows, all clean; suite wall time before and after on both.
- [ ] `cargo clippy --workspace --all-targets` clean on both platforms with
      the new `clippy.toml`; `git grep` for the three functions finds no call
      without an `#[expect]`.
- [ ] If one of the 20 Linux runs fails, the test is named and #207 updated.

**Out of scope:** class D and `startup.rs` rewrites; production timers;
`WaitNamedPipeW`; gating CI on mutants.
