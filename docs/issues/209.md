### 209. The dnstap pump holds no `Busy`, so the drain does not wait for it — **filed 2026-10-10**, **bug**, **needs-info**

Seen while working #208. `Sink::spawn` hands the pump `stop` alone and drops
its `JoinHandle` (`rdns-transport/src/dnstap.rs`). `serve_until_stopped`
drains `Busy` claims, then `main` returns and the runtime drops what is left
(`CLAUDE.md` §9: dropping a `JoinHandle` detaches the task). Nothing orders
the pump's last writes, the queued frames and STOP, before that exit.

Provoked on Linux (WSL, Fedora 44, 157cec4): `rdnsd --dnstap file:...`, 50
queries, SIGTERM, 20 times. All 20 captures ended with STOP, exit 0. So for a
file the pump wins the race in practice.

Not tried: a TCP collector, where STOP is followed by waiting for FINISH, a
round trip the drain does not cover; and `rdnsr`, which spawns its sink the
same way. Either could lose the tail of a capture.

If it is real, the pump holding a `Busy` would make the drain wait for it, and
`rdns::test_util::closed_capture`'s polls could await the drain instead.
