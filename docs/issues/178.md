### 178. `rdnsr` has no control channel: no cache flush, no dump — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

`rdnsctl` connects only to `rdnsd`'s socket (`rdnsctl/src/main.rs:20`, `:78`);
`rdnsr` has no `--control-socket`. SIGHUP re-reads the TLS certificate and the
RPZ files (`rdnsr/src/reload.rs:76`). The caches are cleared only on that path
and only when a nameserver trigger's serial moved (`rdnsr/src/caches.rs:275`,
`answer.rs:843`).

So after fixing a record upstream, an operator waits out its TTL or restarts
the process. Unbound has `flush`, `flush_zone`, `dump_cache`; PowerDNS
Recursor `wipe-cache`, `dump-cache`; BIND `rndc flush`, `flushname`.

`rdnsd`'s control protocol is in `rdns-core/src/control.rs` and Unix-only
(`docs/spec/03` §3.9). A runtime NTA (#176) would want the same channel.

**Triaged 2026-10-06: enhancement, ready-for-agent.**

**Category:** enhancement
**Summary:** give `rdnsr` the control socket `rdnsd` has, sharing its
transport, with cache flush and dump commands.

**Current behavior:** `rdnsr` has no control socket. Its caches are emptied
only by a restart, or on SIGHUP when an RPZ nameserver trigger's serial
moved. The cache can only be cleared whole (`clear`). `rdnsd`'s socket code
(bind, accept loop, conversation, read timeout) is private to `rdnsd`; only
the line protocol is shared (`rdns_core::control`).

**Desired behavior:**

- Move the socket half of `rdnsd`'s control channel — owner-only bind under
  a temporary name and rename, refusal over a live socket, accept loop,
  one-command conversation, read timeout — somewhere both daemons use.
  Each daemon supplies only its command table. One copy (§7); `rdnsd`'s
  tests keep passing unchanged.
- `rdnsr --control-socket PATH`, `control-socket` in `[server]`. Unix-only
  and refused on Windows, as `rdnsd`'s is; #188 is the Windows half for
  both daemons.
- `rdnsctl` is unchanged as a client and reaches `rdnsr` with `-s PATH`.
  Its help text stops listing `rdnsd`'s commands and says the server's
  `help` lists its own.
- Commands:
  - `status`: uptime, the size of each cache, active NTAs (#176), routed
    domains (#172) — each line only once the feature behind it exists.
  - `reload`: exactly SIGHUP's reload, through the same task, reporting
    what it did.
  - `flush`: every resolver cache — answers, negative answers, the denial
    (NSEC) cache, delegations, keys, RTTs.
  - `flushname NAME`: answers and negative answers at exactly `NAME`, all
    types.
  - `flushtree NAME`: answers, negative answers, denials, delegations and
    keys at or below `NAME`. This is the subtree flush #176 needs; build it
    once, whichever lands first.
  - `dump [NAME]`: cached RRsets as zone-file text with remaining TTL, stale
    entries marked, optionally only at or below `NAME`. Copy under the lock,
    write after releasing it (§9).
  - `nta`: list active NTAs with expiry and whether a recheck lifted them.
    No add or remove: the NTA file plus `reload` is the only way in (#176).
  - `version`, `help`.
- Every flush answers with the number of entries removed, so a flush that
  matched nothing says so. Trust anchors and RPZ policy are not caches and
  no flush touches them.

**Acceptance criteria:**

- [ ] `rdnsd`'s control tests pass unchanged against the shared transport.
- [ ] `rdnsr`'s socket is mode 0600 and refuses to bind over a live one.
- [ ] `flushname` of a cached name: the next query goes upstream (count at a
      mock), siblings stay cached; the reply's count is right.
- [ ] `flushtree example.test.`: everything at and below goes, `test.` and
      `other.test.` stay.
- [ ] `flush` empties every cache; `status` shows zeros.
- [ ] `dump` lists a cached RRset with a TTL that has counted down, and a
      stale entry marked.
- [ ] `reload` reports the same outcome SIGHUP would, including a failed
      RPZ reload keeping the old set.
- [ ] An unknown command is refused and names `help`.
- [ ] `--control-socket` on Windows is refused at startup.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      **Linux** (the control code is `cfg(unix)` and Windows never compiles
      it — §1) and Windows, platforms named in the commit.

**Out of scope:**

- A Windows control transport (#188).
- Runtime NTA add and remove.
- Flushing trust anchors or RPZ policy.
