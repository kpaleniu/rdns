### 191. `rdnsr` emits no dnstap — **filed 2026-10-07**, **enhancement**, **ready-for-agent**

Found triaging #189, which wanted somewhere machine-readable to record an
upstream's NSID and found only the log.

dnstap is `rdnsd`'s alone: `rdnsd/src/dnstap.rs`, and nothing under
`rdnsr/src` names it. `rdns::dnstap::MessageType` holds `AuthQuery`,
`AuthResponse`, `UpdateQuery` and `UpdateResponse`; its doc comment says the
resolver-side types "exist in the schema and are not here", because nothing
emits them. Searched every closed item that mentions dnstap — thirteen, plus
`docs/closed/log.md` — for a decision that the resolver should go without:
none makes one.

The schema's resolver-side types are `CLIENT_QUERY`/`CLIENT_RESPONSE` (what a
stub asked and was told) and `RESOLVER_QUERY`/`RESOLVER_RESPONSE` and
`FORWARDER_QUERY`/`FORWARDER_RESPONSE` (what this resolver asked upstream).

No remedy filed: which of those to emit, and whether the existing writer in
`rdns::dnstap` serves both daemons unchanged, is triage's call.

**Triaged 2026-10-07: enhancement, ready-for-agent.**

**Category:** enhancement
**Summary:** `rdnsr` streams dnstap — client traffic by default, upstream
traffic on request — through the writer `rdnsd` already has, moved to where
both can use it.

**Current behavior:** `rdns::dnstap` encodes and frames and does no I/O. The
daemon half — `tcp:`/`file:` target parsing, the writer task, the bounded
queue that drops rather than blocks, `dns_dnstap_frames_total` and
`dns_dnstap_dropped_total` — is `rdnsd/src/dnstap.rs`, and its config keys
are `rdnsd`'s own (`dnstap`, `dnstap-max-bytes`). `MessageType` names only
the authoritative and UPDATE types; its doc comment says "this tree is not a
forwarder or a stub", which `rdnsr` makes false.

Peers: BIND's `dnstap` takes types "`client`, `auth`, `resolver`,
`forwarder`, and `update`", each optionally query or response only. Unbound
has six `dnstap-log-{client,resolver,forwarder}-{query,response}-messages`
switches, each "Default: no".

**Desired behavior:**

- Move the daemon half into `rdns-transport` and use it from both daemons
  (§7). `rdnsd`'s flags, behaviour, counters and tests are unchanged.
- `rdnsr` gains `--dnstap tcp:<addr:port>|file:<path>`,
  `--dnstap-max-bytes`, and the matching config keys, with the same parsing
  and refusals as `rdnsd`, all before `--check-config` returns (§15).
- `--dnstap-types` (`dnstap-types` in config): a comma-separated subset of
  `client`, `resolver`, `forwarder`, BIND's names, each meaning both
  directions. Default `client`. An unknown name, or `--dnstap-types` without
  `--dnstap`, is refused.
- `client`: `CLIENT_QUERY` and `CLIENT_RESPONSE` per client exchange, on
  every transport, with the client's address and the transport.
- `resolver` / `forwarder`: per upstream exchange, the query as sent and the
  response as received in wire form — so EDNS options, NSID (#189) and
  signatures are inside — with the upstream address, the transport, and
  `query_zone` set to the zone the server was asked about. Exchanges with a
  forward-zone server (#172; today, `--upstream`) are `FORWARDER_*`; walk
  exchanges are `RESOLVER_*`.
- The resolver library emits through an optional sink — a callback taking an
  encoded entry — and queues nothing itself. With no sink set, the cost is a
  branch per exchange, `Upstream::Network`'s argument.
- `MessageType` gains the six types, and its doc comment is corrected: the
  claim that this tree "is not a forwarder or a stub" goes, struck in the
  commit message if not in the comment.

**Acceptance criteria:**

- [ ] `rdnsd`'s dnstap tests pass unchanged against the moved code.
- [ ] `rdnsr --dnstap file:…`: one `CLIENT_QUERY` and one `CLIENT_RESPONSE`
      per client query, read back by the module's own reader, and by
      `dnstap -r` if available (§1).
- [ ] `--dnstap-types client,resolver`: a recursion through mock servers
      adds a `RESOLVER_QUERY`/`RESOLVER_RESPONSE` pair per upstream exchange,
      each carrying that server's address and the right `query_zone`.
- [ ] With `--upstream`: `FORWARDER_*` frames, no `RESOLVER_*`.
- [ ] A collector that stops reading: queries are still answered; the
      dropped counter rises.
- [ ] `--dnstap-types bogus` and `--dnstap-types` without `--dnstap` are
      refused, also under `--check-config`.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- Query-only or response-only selection per type.
- A Unix-socket dnstap target (the reason is `rdnsd/src/dnstap.rs`'s header).
- `AUTH_*` frames from `rdnsr` local zones (#174); revisit when it lands.
