### 174. `rdnsr` has no local data except through RPZ — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

Unbound has `local-zone`/`local-data`, BIND serves zones from a resolving
view, PowerDNS Recursor has `auth-zones`. Searched, nothing found:
`local.?zone`, `local.?data`, `static.?zone`, `hosts.?file`, `auth.?zone` in
`rdnsr/src` and `docs/spec/05`, `06`.

The nearest thing is RPZ's local-data action (`Action::LocalData`,
`rdns/src/rpz.rs:74`, read at `:695-727`), which answers any RRset of the
queried type at the trigger. Limits, each checked:

- the owner is rewritten to the QNAME (`rpz.rs:730`);
- AD is clear and EDE 4 (Forged Answer) is attached (`docs/spec/05` §5.6) —
  correct for a policy rewrite, wrong for data the operator owns;
- a CNAME at the trigger is always the action;
- per-name overrides, not a zone: nothing is authoritative or signable;
- it cannot reach anything `special_names` answers first (#173).

`special_names.rs` is a fixed table and not configurable.

## Agent brief

> *This was generated by AI during triage.*

**Triaged 2026-10-06: enhancement, ready-for-agent.** Terms in `CONTEXT.md`:
**Local zone**, and **Routed domain** widened to include it.

**Depends on #172's routing table.** Build on it if #172 has landed; if this
is taken first, build the table as #172's brief describes and add the local
kind to it.

**Category:** enhancement
**Summary:** let `rdnsr` hold zones from zone files and answer from them, as
a third kind of routed domain beside forward and stub zones.

**Current behavior:** the only way to serve the operator's own names is
RPZ's local-data action: owner rewritten to the QNAME, AD clear with EDE 4
(Forged Answer), a CNAME always taken as the action, nothing authoritative,
and nothing under a special-use name or empty zone.

**Desired behavior:**

- A local zone is read by the zone parser `rdnsd` uses
  (`rdns::zone::parse_zone_file_at`) and answered by `rdns::zone_answer`,
  whose header leaves zone *selection* to the caller — that selection is the
  routing table. No second answer engine (§7).
- It is a routed domain: most specific wins, it beats empty zones at the same
  name or below (ADR 0008), and it is consulted wherever #172 routes — CNAME
  hops into and out of it, nameserver-address lookups, validation's fetches.
  A CNAME leaving the zone is followed; a referral inside it is followed as a
  stub zone's would be.
- Header: AA=1, cleared on a referral as `zone_answer` already does. AD never
  set. No EDE: this is the operator's data, not a forged answer. RRSIGs in the
  file are served when DO is set.
- Validating, an answer from a local zone is
  `ValidationState::Indeterminate` with a reason naming the zone, and so is a
  chain that passes through one. The same mechanism as #172's
  `validate = false`, not a second one; no option to validate a local zone.
- Answers from a local zone are not cached, so a reload takes effect at once.
  Answers reached through one — a CNAME target outside, a child behind a
  referral — are cached as usual.
- RPZ runs before local zones as before everything else.
- SIGHUP re-reads local zone files in the existing reload task, with #71b's
  unchanged-file shortcut. All or nothing: one file failing to parse keeps
  the whole old set in force and logs why (§4).

**Key interfaces:**

- `--local-zone NAME=PATH`, repeatable; `[[local-zone]]` tables with `name`
  and `file`, `deny_unknown_fields`. The origin is `NAME`.
- Refused at startup, naming the entry, before `--check-config` returns
  (§15): a file that fails to parse, or has no SOA at `NAME`; a name
  configured twice, or also as a forward or stub zone; a name at or under a
  special-use name.
- The startup banner lists each local zone with file, SOA serial and record
  count, in #172's routed-domain listing. A reload logs each zone whose serial
  moved.
- `docs/spec/05`'s RPZ section: one sentence pointing data the operator owns
  at local zones.

**Acceptance criteria:**

- [ ] A name in a local zone: answered from the file, AA=1, AD=0, no EDE, no
      upstream query.
- [ ] A name absent from it: NXDOMAIN with the zone's SOA, AA=1.
- [ ] A CNAME from a local zone to a public name, and from a public name into
      a local zone, both resolved; the public half is cached, the local half
      is not.
- [ ] A delegation inside a local zone is followed to the child's mock server.
- [ ] A nameserver whose address is in a local zone is reached through it.
- [ ] Validating, with a signed mock parent proving the zone absent: answered,
      Indeterminate, not Bogus.
- [ ] A local zone at `10.in-addr.arpa.` overrides the empty zone; one at
      `localhost.` is refused at startup.
- [ ] An RPZ QNAME rule blocks a name inside a local zone.
- [ ] SIGHUP after editing the file serves the new data; SIGHUP with one
      broken file keeps every old zone and logs the error.
- [ ] Each startup refusal above has a test, including under `--check-config`.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- Signing a local zone; AXFR or IXFR out of `rdnsr`; fetching a local zone
  by transfer (#177 covers the root); UPDATE; NOTIFY.
- Unbound-style single-record `local-data` lines, and hosts files.
