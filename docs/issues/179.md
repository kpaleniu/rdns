### 179. `rdnsd` and `rdnsr` do not answer NSID (RFC 5001) — **filed 2026-10-05**, **needs-triage**

NSID is how an operator asks which instance of an anycast or load-balanced
set answered. BIND (`server-id`), Knot (`nsid`), NSD, Unbound (1.13.1) and
PowerDNS Auth and Recursor all answer it.

Here only the constant exists (`rdns-core/src/edns.rs:129`), and
`ClientEdns::mirror` builds a fresh OPT with payload size and DO alone
(`rdns-core/src/response.rs:463-468`), so a client's NSID request gets no
reply. Searched `nsid` and `5001` over code, `docs/spec/07` and
`docs/closed/021.md`: no row, no decision.

It matters more here than elsewhere because the other answer to "which server
is this", `id.server`/`hostname.bind` in class CH, is refused on purpose
(ADR-0003). NSID is the class-IN form of the same question.
