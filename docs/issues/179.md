### 179. `rdnsd` and `rdnsr` do not answer NSID (RFC 5001) — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

NSID is how an operator asks which instance of an anycast or load-balanced
set answered. BIND (`server-id`), Knot (`nsid`), NSD, Unbound (1.13.1) and
PowerDNS Auth and Recursor all answer it.

Here only the constant exists (`rdns-core/src/edns.rs:129`), and
`ClientEdns::mirror` builds a fresh OPT with payload size and DO alone
(`rdns-core/src/response.rs:463-468`), so a client's NSID request gets no
reply. Searched `nsid` and `5001` over code, `docs/spec/07` and
`docs/closed/021.md`: no row, no decision.

It matters more here than elsewhere because the other answer to "which server
is this", `id.server`/`hostname.bind` in class CH, is refused on purpose
(ADR-0003). NSID is the class-IN form of the same question.

## Agent brief

> *This was generated by AI during triage.*

**Triaged 2026-10-06: enhancement, ready-for-agent.**

**Category:** enhancement
**Summary:** both daemons answer an NSID request (RFC 5001) with an
operator-set identifier, off by default.

**Current behavior:** `EDNS_OPTION_NSID` exists and nothing uses it. Every
reply's OPT comes from `ClientEdns::mirror` / `mirror_with`, and `ClientEdns`
records only whether the client sent an OPT and its DO bit, so an NSID
request is never seen.

**What RFC 5001 requires**, quoted:

- §2.2: a server "that understands the NSID option and chooses to honor a
  particular NSID request" puts its identity in the reply's OPT — optional.
- §2.2: it "MUST ignore any NSID payload data that might be present in the
  query message" and "MUST NOT send an NSID option back to a resolver which
  did not request it".
- §5: the content is the operator's, and "Some of these kinds of
  information are security sensitive".

**Desired behavior:**

- `--nsid VALUE` in both daemons, and `nsid` in the shared `[server]` table
  (`rdns::server_table!`). `VALUE` is ASCII text, or `0x` followed by hex
  for raw bytes. Unset means off. An empty value or bad hex is refused at
  startup, before `--check-config` returns (§15). Off by default for §5's
  reason. The field is split: BIND (`server-id`, default `none`) and
  Unbound (`nsid`, default disabled) ship it off; Knot (`nsid`, default the
  FQDN hostname) and PowerDNS Recursor (`server-id`, default the hostname)
  ship it on.
- A reply carries NSID exactly when the query carried an NSID option and the
  reply carries an OPT — errors included — through the one mirror site, so
  no path can forget it (§7). The query's payload is ignored.
- The option's bytes count against the reply's size limit like any other OPT
  data; a reply that no longer fits is truncated as usual.
- `ClientEdns` records the honoured options a client sent, one field per
  option. #187 (padding) needs the same and must add a field, not reshape
  the type; whichever lands first builds it. The NSID value reaches the
  mirror from configuration, not from the request.
- `rdnsr`'s cache holds records, not wire replies, so an NSID answered to
  one client cannot leak into another's cached reply. Keep it that way.
- The startup banner shows the value, or "off".

**Acceptance criteria:**

- [ ] With `--nsid edge-7`, a query carrying an empty NSID option gets
      `edge-7` back in the OPT, on UDP and TCP, from both daemons.
- [ ] A query without NSID gets no NSID option.
- [ ] A query whose NSID option carries payload still gets the configured
      value, not an echo.
- [ ] REFUSED and NXDOMAIN replies to an NSID query carry it.
- [ ] `--nsid 0x6564` answers the two raw bytes; `--nsid ""` and
      `--nsid 0xzz` are refused, also under `--check-config`.
- [ ] Unset: an NSID query gets no NSID option.
- [ ] A reply sized to exactly the client's payload limit without NSID is
      truncated with it, not sent over the limit.
- [ ] dnspython reads the option back (`dns.edns.NSIDOption`).
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- `rdnsr` sending NSID upstream (#189).
- Defaulting to the hostname.
- `id.server` / `hostname.bind` in class CH (ADR 0003).
