### 175. `rdnsr` sends every upstream query in clear text — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

`rdnsr` serves DoT, DoH and DoQ (#42) but asks upstream only over UDP and TCP:
`upstream::Transport { Udp, Tcp }` (`rdns/src/resolver/upstream.rs:35`).
Searched, nothing found: `tls`, `rustls`, `quic`, `https`, `xot` in
`rdns/src/resolver.rs` and `rdns/src/resolver/`.

Peers: Unbound `forward-tls-upstream`; PowerDNS Recursor `dot_to_port_853`
and `dot_to_auth_names` (4.6.0) and `outgoing.tls_configurations` (5.4.0);
BIND forwards over DoT in 9.21 (landing version not confirmed).

Forwarding to a public resolver is the case that matters, since the clear
hop is the one crossing the internet. A TLS client exists in the tree for
zone transfer (`rdns/src/xot.rs`, `XotClient`) and is not reused by the
resolver.

## Agent brief

> *This was generated by AI during triage.*

**Triaged 2026-10-06: enhancement, ready-for-agent.** Term in `CONTEXT.md`:
**Authentication name**.

**Depends on #172**: TLS is a property of a forward zone's server, and
`--upstream` becomes a forward zone at `.` there. If this is taken first,
attach TLS to today's `upstream_servers` and let #172 carry it over.

**Category:** enhancement
**Summary:** DNS over TLS (RFC 7858) to forward-zone servers, strictly
authenticated, over one persistent pipelined connection per server.

**Current behavior:** `upstream::Transport` is `{ Udp, Tcp }`, a socket per
exchange; every forwarded query crosses the network in clear. `XotClient`
(XFR over TLS) has a TLS 1.3 client with required server authentication and
operator-named trust anchors; the resolver does not use it.

**Desired behavior:**

- Do the refactor first, in its own commit: `XotTrust`, `XotName`,
  `XOT_PORT` become `TlsClientTrust`, `AuthName`, `DOT_PORT` (RFC 7858 §3.1
  and RFC 9103 §7.3 agree on 853), used by both XoT and the resolver.
- A server written `addr[:port]+tls=NAME` in `--forward-zone`, `--upstream`
  or the config's `servers` is asked over TLS only — never UDP first, so no
  truncation step. Parsed by `rdns::endpoint`, as `--secondary` is (§7).
  Port 853 when `+tls=` is given without one. Per server: a zone may mix.
  `#key` on a forward-zone server is refused, not ignored.
- Strict profile only (RFC 8310): TLS 1.3, ALPN `dot`, certificate checked
  against `NAME` and `--upstream-tls-ca`'s anchors. No opportunistic mode
  and no fallback to cleartext: a failed handshake or check makes that server
  unreachable for this exchange, and the next server is tried. None left:
  SERVFAIL with EDE 22 (No Reachable Authority).
- One persistent connection per server. Queries are pipelined (RFC 7858
  §3.3, "clients SHOULD pipeline"), each takes an ID not pending on that
  connection, and a response is matched by ID *and* question (§3.3, "MUST
  match the QNAME, QCLASS, and QTYPE"). Reconnect on failure; close after
  idling, honouring an RFC 7828 `edns-tcp-keepalive` the server sends.
  The pending table is bounded by the existing in-flight limits; no new knob.
- What the server can provoke (§4): a response matching nothing pending is
  dropped and counted, connection kept; a response whose question does not
  match its ID closes the connection.
- The handshake runs under the per-exchange timeout; the resolution timer
  bounds everything, handshake included.
- Queries over TLS carry EDNS padding to a multiple of 128 octets
  (RFC 8467 §4.1(1)).
- Connections close when the shutdown drain completes (`rdns::shutdown`).
- The banner shows each TLS server with its authentication name and the
  anchor count. One counter: upstream TLS handshake failures, since an
  expired certificate at the forwarder otherwise shows only as SERVFAIL.

**Key interfaces:**

- `--upstream-tls-ca PATH`, `upstream-tls-ca` in `[resolver]`: required when
  any server has `+tls=`; refused when none does, or when the file holds no
  anchors. No system trust store (`xot.rs`'s reason; §14). `--help` says how
  to export Windows roots to PEM. Checked before `--check-config` returns.
- No client certificate.

**Acceptance criteria:**

- [ ] Against a local DoT test server with a test CA: a forwarded query is
      answered over TLS, and nothing reaches the server's UDP port.
- [ ] Wrong authentication name, untrusted CA, and TLS 1.2-only server: each
      fails the handshake, the counter moves, the next server answers; with
      no next server, SERVFAIL with EDE 22.
- [ ] Twenty concurrent queries share one connection (one handshake, counted
      at the test server) and all are answered, out of order included.
- [ ] A response with an ID nothing awaits is dropped, connection kept; one
      whose question mismatches closes it, and the next query reconnects.
- [ ] Idle close and reconnect, and a server-advertised keepalive honoured.
- [ ] Sent queries carry padding to a multiple of 128 (assert on the length
      the test server reads).
- [ ] Startup refuses `+tls=` without `--upstream-tls-ca`, the CA flag
      without any TLS server, an empty CA file, and `#key`, also under
      `--check-config`.
- [ ] XoT tests pass unchanged after the rename commit.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.

**Out of scope:**

- DoH and DoQ as upstream transports.
- Encryption to authoritative servers (RFC 9539).
- System trust stores (`rustls-native-certs`, `webpki-roots`).
- TLS 1.2, client certificates, connection pools beyond one per server.
- Padding the listeners' responses (#187).
