### 187. No response is padded when the query asked for it (RFC 7830 §4 MUST) — **filed 2026-10-06**, **needs-triage**

Found triaging #175. RFC 7830 §4 (Standards Track): "Responders MUST pad
DNS responses when the respective DNS query included the 'Padding' option,
unless doing so would violate the maximum UDP payload size." RFC 8467 §4.1(2)
repeats the MUST and recommends blocks of 468 octets.

Neither daemon does, on any transport. Every reply's OPT is built by
`ClientEdns::mirror` / `mirror_with` (`rdns-core/src/response.rs`), and
`ClientEdns` records only whether the client sent an OPT and its DO bit — a
query's option 12 is never read. Checked: no code in the tree builds or
recognises the Padding option (`rg -i padding` finds only RSA signature
padding and test fixtures).

One site builds every mirrored OPT, so the change is likely one place; that
is a reading of `mirror`'s doc comment ("Every such reply goes through
here"), not a measurement of the callers. Which transports to pad beyond the
MUST — RFC 7830 makes padding without a request a MAY — is triage's call.
