### 204. Coverage-guided fuzzing with `cargo-fuzz` — **filed 2026-10-10**, **enhancement**, **triaged 2026-10-10**, **ready-for-agent**

`rdns/tests/no_input_panics.rs` is a hand-rolled mutator: a seeded
xorshift over the six valid messages `corpus()` builds, 250 cases each in
CI. Its module doc rejects `cargo-fuzz` as nightly-only and because random
bytes do not pass the header check. libFuzzer starts from a seed corpus, so the
second reason does not apply if this one is the seed; the first stands, and
is why it belongs in its own workflow rather than in `ci.yml`.

Its `exercise` covers the server's pre-authentication path: admission, TSIG
check, parse, zone lookup, answer writing, re-serialization. Remote-supplied
bytes it does not reach, read from `exercise`:

- `rdnsr`'s handling of upstream responses (`rdns/src/resolver/`,
  `rdnsr/src/answer.rs`), reachable by an off-path spoofer.
- A secondary's parsing of AXFR/IXFR from a primary (`xfr.rs`, `ixfr.rs`).

Wanted: a `fuzz/` crate with targets for these, seeded from the existing
corpus, and a `workflow_dispatch` workflow with a duration input that keeps
the corpus and any crash as artifacts.

Keep or retire the hand-rolled test: it costs under a second and runs on
stable every push. For triage.

## Triage decisions (2026-10-10)

- Targets: (a) the server's pre-authentication path, what
  `no_input_panics.rs`'s `exercise` covers; (b) `rdnsr` parsing upstream
  responses; (c) a secondary parsing AXFR/IXFR responses. The control
  protocol and zone files are not remote input.
- `no_input_panics.rs` stays: stable, every push, under a second. Seeds for
  cargo-fuzz are generated from its corpus, not checked in.
- A crash fails the run and is uploaded; its fix adds the input as a named
  case in a stable test.
- Dated nightly, bumped by hand. `minutes` input, default 10 per target, one
  job per target.

**Category:** enhancement
**Summary:** Add cargo-fuzz targets for the three remote-input paths and a
manually dispatched workflow that runs them.

**Current behavior:** `no_input_panics.rs` mutates six valid messages with a
seeded xorshift, 250 cases each, on every push. It covers admission, TSIG
checking, parsing, zone answers and re-serialization. Nothing fuzzes
`rdnsr`'s handling of upstream responses or a secondary's XFR parsing.

**Desired behavior:**
- A `fuzz/` crate, outside the workspace members so stable
  `cargo build --workspace` is unaffected, with three targets as decided.
- Target (a) calls the same functions `exercise` does. Target (b) drives the
  resolver's response handling with a response to a known query. Target (c)
  drives the code a secondary runs on an AXFR or IXFR response stream.
- Seed corpora written by a generator that reuses the existing corpus
  construction, plus a valid upstream response and a valid transfer for
  (b) and (c).
- A `workflow_dispatch` workflow, one job per target, on a dated nightly,
  `minutes` input default 10. A crash fails the job; crash inputs and the
  grown corpus are uploaded as artifacts.

**Acceptance criteria:**
- [ ] Each target runs locally on Linux for 60 s from its seeds, platform
      stated, and the commit reports executions per second.
- [ ] Stable `cargo build --workspace`, test, clippy and doc are unchanged.
- [ ] A deliberately planted panic in a parsed path is found by its target
      from the seeds within the default time, then removed.
- [ ] The workflow parses (`actionlint`, or the reason it cannot run).

**Out of scope:** fixing what the fuzzer finds (each is its own item);
control protocol and zone-file targets; running on push.
