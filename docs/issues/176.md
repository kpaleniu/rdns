### 176. `rdnsr` has no negative trust anchors (RFC 7646) — **filed 2026-10-05**, **enhancement**, **ready-for-agent**

When somebody else's zone breaks its DNSSEC, the only remedies are turning
validation off globally (`dnssec_validate`, `rdnsr/src/config.rs:107`) or the
client setting CD. RFC 7646 is the per-domain alternative; Unbound has
`domain-insecure` and `unbound-control insecure_add`, PowerDNS Recursor
`rec_control add-nta`, BIND `rndc nta`.

## Agent brief

> *This was generated by AI during triage.*

**Triaged 2026-10-06: enhancement, ready-for-agent.** Term in `CONTEXT.md`:
**Negative trust anchor**.

**Category:** enhancement
**Summary:** time-limited per-domain exemptions from validation, read from a
file re-read on SIGHUP, rechecked and lifted automatically (RFC 7646).

**Current behavior:** a zone with broken DNSSEC is SERVFAIL for every client
until its owner fixes it. The remedies are turning validation off globally,
or every client setting CD.

**What RFC 7646 requires**, quoted so nobody re-derives it:

- §2.1: "An NTA MUST only be used for a limited duration", "Use of an NTA
  MUST NOT be automatic", and it "MUST NOT affect validation of other names
  up the authentication chain".
- §1.1: the validator "treats any upstream responses as if the zone is
  unsigned and does not set the Authentic Data (AD) bit"; "Validation
  starts again if there is a positive trust anchor further down".
- §3: "An NTA placed at a node where there is a configured positive trust
  anchor MUST take precedence over that trust anchor".
- §4: "NTAs MUST expire automatically when their configured lifetime ends.
  The lifetime SHOULD NOT exceed a week." A periodic SOA query at the node,
  removing the NTA once it validates, is what "Implementations SHOULD, by
  default, perform"; "the implementation SHOULD remove all cached entries at
  and below the NTA node" on removal.

**Desired behavior:**

- `--negative-trust-anchors PATH`, or `negative-trust-anchors` in
  `[resolver]`. One NTA per line: `NAME UNTIL [norecheck]`, `UNTIL` an
  absolute UTC time. Re-read by the existing SIGHUP reload task.
- Absolute only: a relative lifetime would restart at every reload and
  never expire. On each load, an `UNTIL` more than 7 days ahead is refused;
  one already past is skipped with a warning; any line that does not parse
  fails the file and keeps the old set in force (§4). Comparisons against
  the wall clock saturate (§6).
- Under an NTA, answers are `ValidationState::Indeterminate` with a reason
  naming the NTA and its expiry, AD clear, no EDE (RFC 8914 has no code for
  it). The same mechanism as #172's `validate = false`, not a second one.
- Scope: names at and below the node only. A positive anchor below it
  resumes validation; an NTA at a node holding a positive anchor overrides
  it, with a warning when loaded.
- Expiry is automatic at `UNTIL`.
- Recheck, unless `norecheck`: every 5 minutes (BIND's `nta-recheck`
  default), an SOA query at the node, validated as if no NTA were there.
  Secure, or provably Insecure: the NTA is lifted in memory and logged. The
  file is never rewritten; a later SIGHUP re-reads it, and the next recheck
  lifts it again. The probe holds `Busy` across the query, not across the
  sleep (§9).
- On add, lift and expiry, cached answers and denials at and below the node
  are flushed. On add, so a SERVFAIL cached before the NTA does not outlive
  it. The cache can only be cleared whole today (`clear`); a subtree flush is
  new, and is built once for both caches.
- Log a line on every add, lift and expiry, with the name and time. A gauge
  of active NTAs.

**Key interfaces:**

- Refused at startup, before `--check-config` returns (§15): the flag and the
  config key together; the NTA file with validation off; a file that fails
  the load rules above.

**Acceptance criteria:**

- [ ] A mock zone with a bad signature: SERVFAIL; add an NTA and SIGHUP:
      answered, AD clear, Indeterminate; the earlier failure is not served
      from cache.
- [ ] A sibling and the parent of the NTA node still validate; a name under
      an NTA with a positive anchor below it validates Secure.
- [ ] An NTA at a node holding a positive anchor overrides it and warns.
- [ ] The NTA expires at `UNTIL` (paused clock), and the subtree is flushed.
- [ ] Fix the mock zone: the recheck lifts the NTA within one interval and
      logs it; with `norecheck` it does not.
- [ ] `UNTIL` eight days ahead is refused; an expired line is skipped with a
      warning; a malformed line on SIGHUP keeps the old set.
- [ ] The gauge follows add, lift and expiry.
- [ ] The startup refusals above, also under `--check-config`.
- [ ] `cargo test`, `cargo clippy --all-targets`, `cargo doc` clean on
      Windows and Linux, platforms named in the commit.
